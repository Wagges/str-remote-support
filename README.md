# STR Remote – Support / Unterstützung

Welcome to the official support and feedback repository for **STR Remote for iOS and Apple Watch**.  
Willkommen im offiziellen Support- und Feedback-Repository für **STR Remote für iOS und Apple Watch**.

## Submit feedback / Feedback einreichen

**[Open feedback forms / Feedbackformulare öffnen](https://github.com/Wagges/str-remote-support/issues/new/choose)**

Choose the form that matches your app and request. You can write in English or German. A free GitHub account is required to submit an issue.  
Wähle das passende Formular für deine App und dein Anliegen. Du kannst auf Englisch oder Deutsch schreiben. Zum Einreichen eines Issues benötigst du ein kostenloses GitHub-Konto.

| App | Bug report / Fehler melden | Feature request / Verbesserung vorschlagen |
| --- | --- | --- |
| iOS | [Report iOS bug / iOS-Fehler melden](https://github.com/Wagges/str-remote-support/issues/new?template=ios-bug.yml) | [Suggest iOS improvement / iOS-Verbesserung vorschlagen](https://github.com/Wagges/str-remote-support/issues/new?template=ios-feature.yml) |
| watchOS | [Report watchOS bug / watchOS-Fehler melden](https://github.com/Wagges/str-remote-support/issues/new?template=watchos-bug.yml) | [Suggest watchOS improvement / watchOS-Verbesserung vorschlagen](https://github.com/Wagges/str-remote-support/issues/new?template=watchos-feature.yml) |

Before submitting, please [check existing issues](https://github.com/Wagges/str-remote-support/issues) to avoid duplicates. Include the app version, device and steps to reproduce a bug. Do not post passwords or private information.  
Bitte prüfe vor dem Einreichen [bestehende Issues](https://github.com/Wagges/str-remote-support/issues), um doppelte Meldungen zu vermeiden. Gib bei Fehlern die App-Version, das Gerät und die Schritte zur Reproduktion an. Veröffentliche keine Passwörter oder privaten Daten.

## Issue organization / Organisation der Issues

Issues are organized using labels rather than folders. The selected form automatically assigns the platform and category labels.  
Issues werden über Labels statt Ordner organisiert. Das gewählte Formular ordnet Plattform und Kategorie automatisch zu.

| Group / Gruppe | Labels | Meaning / Bedeutung |
| --- | --- | --- |
| Platform / Plattform | `ios`, `watchos` | Affected app / Betroffene App |
| Category / Kategorie | `bug`, `enhancement`, `question` | Type of feedback / Art der Rückmeldung |
| Status / Status | `needs-investigation`, `planned`, `in-progress`, `ready-for-test` | Progress / Bearbeitungsstand |
| Priority / Priorität | `priority-high`, `priority-medium`, `priority-low` | Internal prioritization / Interne Priorisierung |

### Maintainer notes / Hinweise zur Verwaltung

Keep issues open while work is pending, add status and priority labels as needed, and close issues once resolved. Existing issues and comments are preserved.  
Lass offene Arbeiten als Issue bestehen, ergänze bei Bedarf Status- und Prioritätslabels und schließe Issues nach der Lösung. Bestehende Issues und Kommentare bleiben erhalten.

The label setup workflow creates or updates the labels and assigns missing category/platform labels to recognizable existing issues.  
Der Workflow zur Label-Einrichtung erstellt oder aktualisiert die Labels und ergänzt fehlende Kategorie-/Plattform-Labels bei erkennbaren bestehenden Issues.
